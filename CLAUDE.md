# CLAUDE.md — Curve Digitizer

You are working on **Curve Digitizer**, a PDF-first, fully in-browser graph digitizer for engineers, part of Open Engineering Tools (openengtools.com). MIT licensed. No login, no cookies, no telemetry, no server-side processing — ever.

## Read these first, in order
1. `docs/PRD.md` — what we are building and for whom. Non-goals in §5 are binding.
2. `docs/ARCHITECTURE.md` — stack, package boundaries, workers, algorithms, CI gates.
3. `docs/PROJECT_SCHEMA.md` — the `.cdz` / `project.json` contract.
4. `docs/MILESTONES.md` — the task you are assigned lives here; respect its dependencies.
5. `docs/ACCEPTANCE_TARGETS.md` — what "done" means for your task.
6. `docs/DECISIONS.md` — settled decisions. Do not re-litigate them; add a superseding entry if you must change one.

## Hard rules
- **Everything in the browser.** No fetch to anything but `'self'`. No analytics, no cookies, no external fonts at runtime (bundle them).
- **Main thread never blocks.** Anything that could take > 50 ms goes to a worker with progress + cancel. Tests assert no long task > 100 ms.
- **All project mutations go through `ProjectStore.dispatch(command)`** with an invertible command. Never mutate the project directly. Every new command gets an apply/invert unit test.
- **Core packages (`core`, `math`, `image`, `trace`, `fit`, `export`) must not import from the DOM, React, or `apps/web`.** `pdf` is the only package that may import EmbedPDF.
- **Image-only mode must always work and be tested without PDFium.**
- **Schema changes = migration + fixture + bump `schemaVersion`.**
- **Licensing:** MIT/BSD/Apache dependencies only. No AGPL/GPL. Check before adding any dependency; record new deps in the PR description with their license.
- **Light theme default; Fluent UI React v9; Fluent System Icons.** No other UI kit.
- **TDD.** Write or extend the failing test first, then implement, then make CI green. Use the `samples/` fixtures where they apply.
- **Do not widen scope.** If a task needs something outside `docs/MILESTONES.md`, open a GitHub issue describing it and stop at the boundary; do not build it.

## Working agreement for agent threads
- Branch from `main`, name `feat/<milestone>-<task>-<slug>` (e.g. `feat/m1-1.3-calibration`). One task per PR.
- Commit and push work in progress at least every 30 minutes of work; cloud sandboxes can be lost.
- Before opening the PR run `pnpm check`. Paste the summary lines of `test`, `test:samples` and `build` size output in the PR description.
- PR description template: **What** / **Why (link task #)** / **How verified** / **Acceptance targets touched** / **New dependencies + licenses** / **Follow-ups (as issue links, not TODO comments)**.
- Open the PR as a normal (not draft) PR when `pnpm check` is green; watch CI and fix it yourself.
- If you cannot reach something you need (a package registry, a sample file, a decision), say exactly what is missing in your first message and stop. Do not mock, guess, or substitute.
- Never: force-push `main`, change CI secrets, add telemetry, change the license, or delete `samples/` ground truth. Changing ground truth requires an ADR entry explaining why.
- Keep `CHANGELOG.md` updated under `Unreleased` for user-visible changes.
- When a decision is needed that `docs/DECISIONS.md` does not cover and that materially changes architecture, schema, or scope: open an issue titled `decision: …`, describe options and your recommendation, pick the recommendation, record it in `docs/DECISIONS.md`, and proceed. Do not wait. Only stop for decisions that cannot be undone (deleting data, changing the public file format in an incompatible way, adding a dependency with an unclear license).

## Code conventions
- TypeScript strict; no `any` without a comment; prefer `readonly` and discriminated unions.
- Numeric code lives in `packages/math` with doc comments giving the formula and a fixture test against NumPy/SciPy values (store fixtures as JSON under `packages/math/fixtures/`, generated by `scripts/gen-fixtures.py` which is checked in).
- Workers: typed Comlink interfaces in `packages/workers/src/api.ts`; transfer buffers, never copy; honour the cancel flag every ≤ 10 ms of work.
- React: function components, hooks, Zustand for UI state only. No business logic in components.
- Accessibility: every control has a label; keyboard reachable; axe in e2e must pass.
- Naming: `Graph` (one figure), `Dataset` (one curve), `Point`, `Calibration`, `Fit`. Do not introduce synonyms.
- Comments explain *why*; the code explains *what*. No commented-out code.

## Where things go
- New filter op → `packages/image/src/ops/` + registry + unit test + docs entry in `docs/content/preprocessing.md`.
- New fit model → `packages/fit/src/models/` + registry + all six code generators + A7/A8 tests.
- New command → `packages/core/src/commands/` + invert test.
- New export → `packages/export/` + golden file test.
- New sample → `samples/<name>/` with `source.png`, `ground-truth.json`, `ops.json`, `README.md`.
- Docs pages → `docs/content/*.md` (served at `/docs`).
